## 1. Overview

Unit 1 infrastructure covers the database setup, environment configuration, and local filesystem requirements. No application server is running in Unit 1 — this is purely the data layer and configuration foundation.

## 2. PostgreSQL Database

### 2.1 Local Development Options

Two options are supported for local development. Developers choose based on their preference.

#### Option A: Docker Compose (Recommended)

```yaml
# docker-compose.yml (at workspace root)
version: '3.9'

services:
  postgres:
    image: postgres:15-alpine
    container_name: tms_postgres
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: password
      POSTGRES_DB: tms_dev
    ports:
      - "5432:5432"
    volumes:
      - tms_postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  tms_postgres_data:
```

**Commands**:
```bash
# Start PostgreSQL
docker compose up -d postgres

# Stop PostgreSQL
docker compose down

# Reset database (delete all data)
docker compose down -v
docker compose up -d postgres
```

**Connection string for Docker**:
```
DATABASE_URL="postgresql://postgres:password@localhost:5432/tms_dev"
```

#### Option B: Local PostgreSQL Install

For developers who prefer a local PostgreSQL installation:

```bash
# macOS (Homebrew)
brew install postgresql@15
brew services start postgresql@15
createdb tms_dev

# Ubuntu/Debian
sudo apt install postgresql-15
sudo systemctl start postgresql
sudo -u postgres createdb tms_dev
```

**Connection string for local install**:
```
DATABASE_URL="postgresql://postgres@localhost:5432/tms_dev"
```

### 2.2 Database Configuration

| Parameter | Value | Notes |
|---|---|---|
| Engine | PostgreSQL 15+ | Minimum version for JSON operators used |
| Database name | `tms_dev` (dev), `tms_prod` (prod) | Separate databases per environment |
| Port | 5432 | Default PostgreSQL port |
| Connection pooling | Prisma default (10 connections) | Sufficient for MVP |
| SSL | Disabled (dev), Enabled (prod) | Railway/Render enforces SSL |

### 2.3 Prisma Connection Configuration

```prisma
// backend/prisma/schema.prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}
```

Prisma reads `DATABASE_URL` from the environment. The connection string format:
```
postgresql://USER:PASSWORD@HOST:PORT/DATABASE?schema=public
```

For Railway/Render, the `DATABASE_URL` is provided automatically by the managed PostgreSQL add-on and includes SSL parameters.

## 3. Prisma Migrations

### 3.1 Migration Storage

Migrations are stored in `backend/prisma/migrations/` and committed to source control.

```
backend/prisma/
├── schema.prisma
├── seed.ts
└── migrations/
    └── 20240101000000_init/
        ├── migration.sql
        └── README.md (auto-generated by Prisma)
```

### 3.2 Initial Migration Content

The initial migration (`_init`) creates all tables defined in the schema:

```sql
-- CreateEnum
CREATE TYPE "Role" AS ENUM ('ADMIN', 'TEAM_LEADER', 'TEAM_MEMBER', 'JUNIOR_MEMBER');
CREATE TYPE "TaskStatus" AS ENUM ('TODO', 'IN_PROGRESS', 'REVIEW', 'DONE');
CREATE TYPE "Priority" AS ENUM ('LOW', 'MEDIUM', 'HIGH', 'URGENT');
CREATE TYPE "AvailabilityStatus" AS ENUM ('AVAILABLE', 'IN_CALL', 'AWAY', 'OFFLINE');
CREATE TYPE "MessageType" AS ENUM ('TEXT', 'FILE', 'IMAGE', 'LINK');
CREATE TYPE "ProjectStatus" AS ENUM ('ACTIVE', 'ON_HOLD', 'COMPLETED', 'ARCHIVED');

-- CreateTable: users
CREATE TABLE "users" (
    "id" TEXT NOT NULL,
    "email" TEXT NOT NULL,
    "name" TEXT NOT NULL,
    "password" TEXT NOT NULL,
    "role" "Role" NOT NULL DEFAULT 'JUNIOR_MEMBER',
    "availabilityStatus" "AvailabilityStatus" NOT NULL DEFAULT 'OFFLINE',
    "avatarUrl" TEXT,
    "supervisorId" TEXT,
    "createdAt" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    "updatedAt" TIMESTAMP(3) NOT NULL,
    CONSTRAINT "users_pkey" PRIMARY KEY ("id")
);

-- (additional CREATE TABLE statements for all models)

-- CreateIndex
CREATE UNIQUE INDEX "users_email_key" ON "users"("email");
CREATE UNIQUE INDEX "refresh_tokens_tokenHash_key" ON "refresh_tokens"("tokenHash");
CREATE UNIQUE INDEX "group_members_groupId_userId_key" ON "group_members"("groupId", "userId");

-- AddForeignKey (all foreign key constraints)
```

### 3.3 Migration Commands

```bash
# Development: create and apply migration
cd backend
npx prisma migrate dev --name init

# Development: apply pending migrations without creating new ones
npx prisma migrate dev

# Development: reset database (drop, recreate, migrate, seed)
npx prisma migrate reset

# Production: apply pending migrations only (no reset, no seed)
npx prisma migrate deploy

# Generate Prisma client after schema changes
npx prisma generate

# Open Prisma Studio (database GUI)
npx prisma studio
```

## 4. Environment Variables

### 4.1 Complete Variable Reference

| Variable | Required | Default | Description |
|---|---|---|---|
| `DATABASE_URL` | Yes | — | PostgreSQL connection string |
| `JWT_SECRET` | Yes | — | Secret for signing access tokens (min 32 chars) |
| `JWT_REFRESH_SECRET` | Yes | — | Secret for signing refresh tokens (min 32 chars, different from JWT_SECRET) |
| `PORT` | No | `4000` | HTTP server port |
| `NODE_ENV` | No | `development` | Environment: `development`, `test`, `production` |
| `CORS_ORIGIN` | Yes | — | Allowed CORS origin (frontend URL) |
| `UPLOAD_DIR` | No | `./uploads` | Directory for uploaded files |
| `ANTHROPIC_API_KEY` | No* | — | Anthropic Claude API key (*required for AI routes) |

### 4.2 Secret Generation

```bash
# Generate JWT_SECRET (32 random bytes as hex = 64 chars)
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

# Generate JWT_REFRESH_SECRET (different value)
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### 4.3 Environment-Specific Values

| Variable | Local Dev | Production |
|---|---|---|
| `DATABASE_URL` | `postgresql://postgres:password@localhost:5432/tms_dev` | Provided by Railway/Render |
| `CORS_ORIGIN` | `http://localhost:5173` | `https://your-app.vercel.app` |
| `NODE_ENV` | `development` | `production` |
| `PORT` | `4000` | Provided by Railway/Render |
| `UPLOAD_DIR` | `./uploads` | `/app/uploads` or volume mount path |

## 5. Local /uploads Directory

### 5.1 Directory Creation

The `/uploads` directory is created automatically on backend startup:

```typescript
// backend/src/index.ts
import { mkdirSync, existsSync } from 'fs';
import path from 'path';

const uploadDir = process.env.UPLOAD_DIR ?? './uploads';
const absoluteUploadDir = path.resolve(uploadDir);

if (!existsSync(absoluteUploadDir)) {
  mkdirSync(absoluteUploadDir, { recursive: true });
  console.log(`[Startup] Created uploads directory: ${absoluteUploadDir}`);
}
```

### 5.2 Directory Structure

```
backend/
└── uploads/              ← created on startup, gitignored
    ├── .gitkeep          ← ensures directory is tracked in git
    ├── avatars/          ← user avatar images (created by FileComponent)
    ├── attachments/      ← task and message attachments
    └── ai-uploads/       ← files uploaded for AI processing
```

### 5.3 Static File Serving

The Express server serves uploaded files as static assets:

```typescript
// backend/src/index.ts (Unit 2+)
import express from 'express';
import path from 'path';

app.use('/uploads', express.static(path.resolve(env.UPLOAD_DIR)));
```

Files are accessible at: `http://localhost:4000/uploads/filename.ext`

### 5.4 .gitignore Configuration

```gitignore
# Uploaded files — not committed to source control
uploads/*
!uploads/.gitkeep
```

## 7. Prisma Schema Validation

Before running migrations, validate the schema:

```bash
# Validate schema syntax
npx prisma validate

# Format schema file
npx prisma format

# Check for schema drift (production only)
npx prisma migrate diff \
  --from-migrations ./prisma/migrations \
  --to-schema-datamodel ./prisma/schema.prisma \
  --shadow-database-url $SHADOW_DATABASE_URL
```
